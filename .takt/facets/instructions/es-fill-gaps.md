# 指示: 指摘された不足を実コードから補う

前ステップ(lint)が列挙した不足を、対象 `.es` に**実コードの evidence を読んで**埋めよ。捏造禁止。

## 手順（不足の種別ごと）

- **R1 payload無し（event/readmodel）**: そのイベントが運ぶ項目を `fields=名:制約;…` で列挙。各項目は
  evidence のクラス/フィールド定義を読み、型・制約・取りうる値を実値に解決する。
- **R2 構造無し（aggregate）**: `fields=`（AND合成・`?`任意・`[a|b|c]`OR分岐）か `states=`（状態機械）を書く。
  **フラグやステータスコードは `states=`＋`transitions=` へ昇格**（kawasima指針）。
- **R3 behavior無し（command/policy）**: `in=` `out=X|Y` `decide="…"` を書く。
- **R6 出所未定義（policy.in）**: 読む項目が、どこかの fields/states に定義されるようモデルを補う（必要なら
  リードモデルや集約に項目を足す）。
- **R7 述語未定義**: decide の複合条件に出る言葉（「期限内」等）を `behaviors=名: in -> out // 定義(計算ルール)` で定義。
- **R4 制約なし**: field に `:型/制約` を足す。 **R5 臭い**: フラグ/コード名を `[0=…|1=…]` か states へ。
- **裸ジャーゴン（check-jargon）**: 説明なしで使った記号/専門用語（Tx-ID・p50・SLI 等）を、初出で日本語併記に直す
  （例「取引ID(取引を一意に識別する番号)」）。提案文言が指摘に出るのでそれに従う。
- **evidence ドリフト（check-es-evidence）**: 指された file が実在しない → 正しい file:line に直す（コードを
  `Grep`/`Glob` で探す）。実在しなければ仮説として `evidence=設計` 等に格下げするか hotspot 化。

## 制約

- **命名規約厳守**（コマンド=現在形動詞 / イベント=過去形 / ポリシー=条件 / 集約=名詞）。
- **マジックナンバーは「数字=意味」併記**。
- コードだけで決められない値の意味・意図vs欠陥は、無理に埋めず `discuss=`（何を議論・決めるか）として残す。
- 1ノード1責務で、文法ゲートを壊さない（編集後に lint が再判定する）。
