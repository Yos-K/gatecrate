# ADR-0002: 移植境界は「層」でなく「判定の構造性」で引く

状態: 承認済み

## 決定事項

Rust と sh の境界は、スクリプトがゲートか射影かという**層**ではなく、**判定ロジックが構造
（パーサ・グラフ探索・集合演算）を持つか**で引く:

- **Rust へ**: 判定が形式のパース・グラフ探索・集合の推論を含むもの。実務閾値は
  「**埋め込み awk が約30行を超えたら移植のシグナル**」。
- **sh のまま（凍結でなく正解として）**: 正規表現1本・ファイル存在で終わる検査。kit の
  「1ファイル cp で採用完了」という消費モデルを保ち、**probe-gate-liveness との互換**も保つ
  （probe はスクリプト単体を使い捨てリポへコピーして違反を注入する。シム化ゲートは単体では
  動かない——binary 不在は exit 2 なので偽 ALIVE にはならないが、生存証明の対象にできない）。
- 既存の Rust ゲート2本（adr-review・interaction-traceability）は原型検証のための移植であり、
  **kit 自身の CI 用**。消費者は sh 版を使い続ける。二重実装はこの役割分離と、双方が独立の
  挙動テストを持つことで管理する。

移植の不変条件（計画から変更なし）: 出力形式と exit 契約は凍結・既存 sh 挙動テストが受け入れ
テスト・1本ずつ移行。

## 検討した選択肢

1. 全部 Rust へ移植する
2. 層で凍結する: ゲートは全部 sh のまま、射影・計測だけ移植（計画レビュー時の当初案）
3. 現状維持: これ以上移植しない
4. 本決定: 判定の構造性で境界を引く

## 選択理由

- **2つのエージェントが、別の日・別のプロジェクトで同じ欠陥クラスを踏んだ**——変数展開事故・
  sed の不発が生む偽のテスト結果・行指向パースが構造の違う入力を通す——そして
  **shellcheck -S error はどれも検出しなかった**。全件が「構造を持つ判定」のコードで起き、
  正規表現1本の検査では起きていない。
- リポの実測とも一致する: 痛いスクリプトは awk 密度の高いものと正確に重なる
  （measure-modularity awk 10箇所・es-coverage 8箇所・es-render-html は800行だった）。
- 痛みの診断は「構造データを行指向ツールで扱っていること」。だから処方は「構造があるところに
  型付きパースを」であり、構造が無いところには何もしないこと。

## 選択しなかった理由

- **全部移植**: 型の恩恵が無い単純ゲートまで「1ファイル cp」の消費モデルと probe 互換を壊し、
  消費者が求めていない toolchain 要求を足す。
- **層で凍結**: 両方向に誤分類する——es-lint はゲートだがパーサの塊（Rust に値する）、
  check-adr-review はゲートだが構造が薄い（消費者向けは sh で足りる）。この誤りは consumer 側
  エージェントの独立レビューが指摘した。
- **現状維持**: モデルと計測を判定するコードに、実証済み・shellcheck 非検出の欠陥クラスを残す。

## 決定を見直す契機

- probe-gate-liveness がシム/バイナリ越しの注入を覚えた（probe 制約が消える）
- 消費者が Rust ゲートを明示的に求めた（2本の役割分離を再訪）
- 「sh のまま・単純」と分類したスクリプトに構造判定が生えた（awk 30行シグナルの発火）
- 原型検証ゲート2本の実装間で観測可能な挙動差が出た（どちらかに寄せる判断を強制）
