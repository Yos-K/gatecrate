# ADR-0001: Rust 実装はソース配布を第一とし、プレビルトは保留する

状態: 提案中（未確定の入力が1つ: Termux 実機検証）

## 決定事項

消費者は Rust 実装を**ソースからビルド**して得る（kit checkout で `cargo build --release`、
または消費者 CI の同等ステップ）。バージョンの pin は kit の git tag —— `sync-manifest.yaml` が
既に持っている pin と同じ軸。シムはバイナリを `GATECRATE_BIN` → kit 自身の `target/` → `PATH` の
順で解決し、無ければ exit 2 で明示的に失敗する（黙って劣化しない）。

プレビルト配布（cargo-dist / cargo-binstall）は**却下ではなく保留**: crate 構成は lib-first なので、
後から配布形態を切り替え・追加しても変更は薄い bin 層と本記録だけで済む。

## 検討した選択肢

1. **プラットフォーム別の単一プレビルトバイナリ**（cargo-dist → GitHub Releases・サブコマンド CLI）
2. **ツール別プレビルトバイナリ**（consumed_scripts の opt-in 粒度を鏡写しにした個別 artifact）
3. **ソース配布第一**（本決定）: 消費者がビルドする。ビルドできない実消費者が現れたときだけ
   プレビルトを足す

## 選択理由

パイロット（es-render-html・依存は clap のみ）での実測:

- cold `cargo build --release` は **CI ランナーで 12.7 秒**（キャッシュなし・lint ジョブ全体は
  30秒→43秒）、**ローカルで 9.3 秒**。プレビルトが取り除くはずのコストが、現状は挙動テスト
  1スイート分より小さい。
- **シム化されたスクリプトを消費している consumer はまだゼロ**。消費者が現れる前にリリース基盤を
  作るのは AGENTS.md の言う「未実証の汎用性」そのもの。
- ソース配布は kit の監査可能性を保つ: 消費者が実行するものは pin した tag で読めるテキストと
  正確に一致し、`check-kit-drift` に第2のバージョン軸を足さずに済む。

## 選択しなかった理由

- **単一プレビルト**: 全ゲートのリリースサイクルが結合し、ドリフト検査にバージョン軸が増える。
  唯一の実利（toolchain 不要）は、現時点でどの消費者も持っていない問題を解く。「決定を見直す契機」で再訪。
- **ツール別プレビルト**: 約95ツール×5プラットフォームの artifact とバージョン行列。守りたかった
  opt-in 粒度はシム＋lib-first の features で既に守られている。

## 決定を見直す契機

- Termux 実機検証が失敗する（`cargo build` できない消費者環境の実在）、またはシム化スクリプトを
  採用した実消費者がソースビルドできない。
- cold build が約60秒を超える（依存の増加）、または消費者 CI がキャッシュを持てない。
- シム化スクリプトの採用消費者が3つに達する（規模の経済がプレビルト側へ傾く）。
