# gatecrate を使った開発の流れ — 二重ループ・モデル

English: [development-workflow.md](./development-workflow.md)（正文書）。本書はその日本語補足訳。

gatecrate の各部品が、開発ライフサイクル全体としてどう噛み合うか。**何がいつ走り、どの資産が何を担い、
どこで人間が判断するか**を最初に掴むための概観。

## 核心：速度の違う2つの入れ子ループ

ハーネスには**一階ループ**（*コード*を縛る）と**二階ループ**（*自分自身*を縛る）がある。両者は
回る速さが違い、これを混同するのが典型的な失敗。

進化的アーキテクチャ（Ford / Parsons / Kua）の言葉では、一階ループは漸進的変更を導く**適応度関数**の
集合であり、二階ループは書籍が手動プラクティスに留めた「適応度関数を定期レビューせよ」の機械化に
あたる: probe が各予防型適応度関数の計測能力を検査し、型分類が計測値の読み方自体を決め
（予防ゲートの発火0は健全・検出ゲートの発火0は削除シグナル）、ROI 判定が剪定を提案する——承認は人間。
運用上の帰結が2つ: 絶対 floor でなく **ratchet 型**（導関数述語＝「ベースラインより悪化していない」）を
選ぶ（初日に落ちる floor は関数ごと外され、適応度もろとも失われる）。そして機械判定可能なもの
（exit code）と判断（意味的分類）を分離する——エージェントはその間に立ち、人間の上には立たない。

```
┌─ 内側ループ — 高速・毎PR ─────────────────────────────────┐
│   2. エージェント実装 → 3. CIゲート実行 → 結果を読む        │  ← コードを直す
│        ▲────────────────────────────────────────┘         │
└───────────────────────────────────────────────────────────┘
            │  （履歴が溜まったら時々）
            ▼
┌─ 外側ループ — 低速・周期的・非ブロッキング ───────────────┐
│   4. ハーネス評価 → 5. 判定 → 6. 是正                      │  ← ハーネスを直す
│        └───────────────► 設定 / プロファイルへ反映 ────────┘
└───────────────────────────────────────────────────────────┘
```

**なぜ2つの速さか（なぜ→だから）**: 外側ループの ROI 評価は*溜まった証拠*（発火実績・CIコスト履歴・
プローブ結果）を前提にする。毎PR 回すと雑音になる。**だから**外側ループは時々回し、内側ループを
**止めてはならない**——さもないとメタハーネスが第二のプロダクトになり、機能開発を窒息させる
（方法論が警告する実在の失敗モード）。**だから 6 は次の周の 2 と並行**して走る：遅いループが速いループを
ゲートしない。

## 6ステップと資産の対応

| # | ステップ | 資産 | 周期 |
|---|---|---|---|
| 1 | CIハーネス構築 | `gatecrate-setup` スキル + `install.sh` + profiles。**どの検証を入れるかは `test-selection-roi`**（PBT / ステートフル PBT / mutation / モデル検査） | 一度（時々再プロファイル） |
| 2 | エージェントがコード実装 | Claude Code / 任意のエージェント | 変更ごと |
| 3 | CI実行 | 予防 + 検出ゲート、**生存証明プローブ**（`probe-gate-liveness.sh`）、doc-currency 等 | 毎PR |
| 4 | **ハーネスの評価** | `collect-gate-history.sh`（発火/コスト）+ probe + git churn → **`gatecrate-evaluate`** → ROIレポート（5判定） | 周期的 |
| 5 | 追加/修正/削除の判定 | 5判定。*何を足すか*は `test-selection-roi` | 周期的 |
| 6 | 判定の実施 | strengthen=テスト追加 / consolidate=自動化 / remove=人間承認PR / DEADゲート修理=`harness-liveness-converge`(TAKT) | 周期的・次の2と並行 |

ステップ4→6（外側ループ）は実行可能アーティファクトとして packaging 済み。ループは緊張する2つの半分を持つ:
**剪定**（lean に保つ）と**拡充**（カバレッジを増やす）。

- **剪定** — `harness-evaluate-cycle`（計測→評価→ルーティング）。1回の起動で日付付きレポート（5判定）を書き、
  アクションをルーティングする（修理は `harness-liveness-converge` へ・撤去は人間承認の提案へ）。
- **拡充** — 3アーティファクト: `harness-coverage-deepen`（Deepen）は survivor を殺すテストを mutation ゲートが
  clean になるまで足す converge ループ（機械的シグナルから成長）。`harness-coverage-expand`（Broaden）は
  scan→assess→propose で、変更クラスタのうち**リスク形状はあるが検証が無いもの**に*新技法*を提案。
  `harness-rule-reflect` はその技法が検証する**ルール**をミニ言語（ID付き）で文書化し、テスト*と*——順序/状態
  ルールなら——Alloy モデル assert に反映する（1ルール=2反映で、テストとモデルが1ソースから育つ）。
  提案/scaffold レベル・人間の意図vs欠陥ゲート付き。設計: [design/expansion-loop.md](./design/expansion-loop.md)、
  [spec-rules.ja.md](./spec-rules.ja.md)。

TAKT が順序付けと監査を担い、判断は persona に残す。拡充は剪定より自律的でよい（テスト追加は安全・ゲート削除は危険）。
2つの半分が釣り合う——拡充が増やし、剪定が刈る。

## 「評価」は2種類ある — 混同しない

ステップ4は「CI結果を読んでコードを直す」**ではない**。それ（*テストが落ちた→コードを直す*）は
**内側**ループ（2→3 の中）。ステップ4は**ハーネス自体の評価**：*このゲートは効いているか・黙って
壊れていないか・冗長でないか*。ステップ4=`gatecrate-evaluate` と固定すれば曖昧さは消える。

## 人間ゲートは外側ループに在る

外側ループは**完全自律ではない**——設計上:

- **removal / consolidate は提案**で、人間が承認する。安全制約（シークレット・禁止権限）は
  メトリクスで自動撤去しない。
- **エスカレーション専用ゲートは自動修理から除外**。修理が人間専有のゲート（セキュリティ所有のポリシー、
  前提消滅→撤去提案）は `# gatecrate-scope: escalation-only` を持ち、converge ループ（`--repairable-only`）が
  SKIP する。これは exp3 の発見への構造的修正：converge-to-green ループは「human-owned ゲートを編集しない」
  ことを信頼できないので、そもそも見せない。**だからステップ6には「自動修理可」と「人間へエスカレーション」の
  2分岐がある**。

## フィードバックの矢印：6 → 1

外側ループは直線でなく環。`consolidate` / `removal` の所見は、プロジェクトの**プロファイル選択**
（どの段のハーネスを回すか）に反映される（harness-roi-evaluation の「Connection to profiles」）。
つまりステップ6の実施が、次の周の 1/2 が走るハーネスの形を変える。

## 実例（本リポジトリ・2026-06-14）

gatecrate 自身での**外側**ループ一周:

- **4 計測**: CI 40 runs——全ゲート `fires=0`、ShellCheck がゲート秒の約60%（コスト外れ値）;
  生存証明: 予防ゲート全て ALIVE。
- **5 判定**: 軸1 → `removal = 0`（全層が安価か独自）。軸2 → `consolidate-candidate` 1件:
  **EN/JA ドキュメントが手作業規律で同期**され、機械的強制が無い。
- **6 実施**: `check-doc-currency.sh` を出荷（`*.md`/`*.ja.md` 対の片側だけ編集した PR を落とす）し
  CI に配線——手作業規律を自動ゲートに置換。

レポート全文: [evaluations/2026-06-14.md](./evaluations/2026-06-14.md)。これが二階ループの実働:
ハーネスが自分の維持負荷を計測し、ギャップを閉じた。
