**直近: 実 Java レガシーでの end-to-end 検証（バグ1件発見・修正＋Java対応追加）**。ある実運用の Maven Java モジュール
（jacoco 0.8.11・`jacoco.coverage.minimum=0.55` の絶対floor）で diff-coverage を実証。**実バグ発見**: `check-diff-coverage.sh`
の JaCoCo パーサが `tr '>' '>\n'` で要素分割していたが tr は文字を**挿入できない**（1:1変換のみ）ため、改行の無い**単一行の
実 jacoco.xml（約750KB）を分割できず全行 nothing-to-gate**になっていた。fixture が偶然複数行だったため単体テストをすり抜けて
いた（実データ検証の価値）。→ `awk RS=">"` に修正（macOS の `sed 's/>/>\n/'` は `\n` を literal n にする罠ゆえ awk が唯一移植的）。
**反例を単体テスト化**: property8（単一行XML）を追加し回帰固定（14アサーション緑）。**実証**: 実ソースの被覆行100＋未被覆行76を
実編集→実 git diff（`@@ -76 +76 @@`）→実XML突合で「50%<floor80→FAIL（76を名指し）/ floor50→pass」を確認。
**Java 対応の穴も発見・解消**: 対象が全て Java なのに雛形が Kotlin のみだった→ `Approvals.java.example` /
`ExampleCharacterizationTest.java.example` を追加し **JDK21 javac で実コンパイル＋JUnit5 実行スモーク（received 生成＆初回fail）
まで確認**（Kotlin 版はローカル kotlinc 無しで未コンパイルのまま）。`check-no-received-approvals` も実リポで pass/
混入時 FAIL を確認。**環境メモ**: 対象の各モジュールは別リポの git worktree で worktree 管理リンクが壊れており、その場では
git 操作不可（ゲートのバグではない）。検証は実XML＋実ソースを隔離 temp リポに置く方式で実施（元リポは無改変）。

**直近: レガシー（テスト無し）対応 — 差分カバレッジ ratchet レーン**。gatecrate のテストレーンは絶対 floor
（`coverage>=80`）型ゲートしか出荷しておらず、テストの無いレガシーに入れると初日に必ず落ち→ゲートごと外され→安全網が
育たない、という穴があった。概念モデルで言うと**水準述語**（あなたは十分良い）しか無く、レガシーに効く**導関数述語**
（悪化していない/触った所は良くなっている＝ratchet）が欠けていた。これを `core/scripts/check-diff-coverage.sh`
（detection・差分カバレッジゲート）で補填: このPRで**追加/変更した行だけ**に被覆を要求し（既定 floor 80%・`>=`）、レガシー
本体には一切手を入れさせない（＝ボーイスカウトルールの機械強制）。入力は **JaCoCo XML** のみ（Kotlin/Android は
kover/jacoco が出せる）で、判定（git diff の変更行 ∩ 被覆報告）はスタック非依存。報告フォーマットだけ `COVERAGE_FORMAT`
でパラメータ化（現状 jacoco）。外部 diff ドライバ（difftastic 等）対策に `--no-ext-diff` で標準 unified hunk を強制。
**設計上の選択**: ユーザー提示の「run-tests.sh に mode 追加」案より、被覆生成（run-tests）と差分ゲート（diff-coverage）を
**分離した独立ゲート**にした（理由: 1ファイルで Kotlin/Android/将来 lcov・coverage.py を賄え、単体テスト可能、関心が分離）。
挙動テスト `tests/test-check-diff-coverage.sh`（7性質12アサーション・全PASS・手動欠陥挿入2件で検出力確認）。
新プロファイル `profiles/brownfield.yaml.example`（minimal + diff-coverage）。setup skill に「テスト有無で
standard/full か brownfield か分岐」を追記。解説 `docs/test-selection-roi.md`（EN/JA）「レガシー（テスト希薄）の入口」。
**自己ハーネス全通過**: 26 behavior tests・POSIX・gate-classified（detection に分類）・gate-tests・doc-currency・300行。
**既知の限界**: 報告に現れない変更行（テストで一度もロードされない新規ファイル等）は未計装として分母外＝被覆要求が掛からない
（diff-coverage 一般の限界。新規ファイルの取りこぼしが痛い場合は test 存在ゲートで補う）。

**ROADMAP P4「ROI 自己収縮」の型分類サブサイクルが step2 まで完了**。設計判断は
[`docs/probe-scope-and-gate-classification-decision.md`](../probe-scope-and-gate-classification-decision.md) に正典化済み（§2〜§3.2）。
ROI 剪定は「予防型 fires=0(正常)」と「検出型 fires=0(削除候補)」を発火履歴だけで区別できないため、各ゲートに**型**が要る。
型は手貼りでなく**構造から導出**し、人間に委ねる箇所は**判断材料（証拠＋推論のはしご）を添えて提案**する（自動適用しない）。

到達点（PR #100〜#106）:

- **§3 step1 — 型導出**: `core/scripts/classify-gate-type.sh`。`--one <gate>` で
  `not-a-gate`（ハーネスのツール）→ `prevention`（reject レジストリ在籍）→ `# gatecrate-type:` マーカー（人間上書き）→ `untyped` の順に導出。
  単一ソース化のため probe に `--list-reject-gates` を追加。意味的誤分類は検出しない（在籍が一次・是正は人間 escalation）。
- **§3.1 — 3カテゴリ精緻化**: `prevention`/`detection`/`advisory`+`untyped`+`not-a-gate`。advisory（非ブロッキング）は発火ベース ROI 判定の
  対象外。「ブロックするか」はモード(`--strict`)とCI配線(required か)依存ゆえスクリプト単体では導出不能→人間マーカー。
- **§3.2 — 判断材料 `--explain`**: 派生証拠（非0exit/registry/--strict/advisory自己宣言/test/workflow）+ needs-gh 明示 + suggested type を
  **推論のはしご**（observe→select→assume→conclude・未検証段は `[UNVERIFIED]`+「check first」）で提示。飛躍が無ければはしごを畳む。
- **§3 step2 — untyped メタゲート**: `core/scripts/check-gate-classified.sh`。GATE_DIR の全 *.sh を分類し untyped があれば fail、
  失敗時に `--explain` の判断材料を載せる（バレ丸投げにしない）。untyped のみ叱る（advisory/not-a-gate は終端で叱らない）。
  self-harness に配線（blocking）。**kit を 0 untyped に収束**: prevention13／advisory4／detection1／not-a-gate10。
- **§3 step3 — 型別 axis-1 verdict（§3 完結）**: `core/scripts/gate-roi-verdict.sh`。`collect-gate-history` の発火 TSV を型で解釈し
  verdict を機械化。**prevention fires=0→keep（反事実の罠回避）／detection fires=0×高コスト→removal-candidate（②uniqueness は人間 flag・
  提案のみ・自動削除しない）／detection fires=0×安価→keep（①不成立）／detection fires>0→keep／advisory→human-judgment／not-a-gate→skip**。
  axis-2・②uniqueness・risk-gone・consumed? は skill/人間の領分（過剰主張しない）。verdict は非ゲートゆえ NON_GATE 登録。テスト lint 配線。

## 判断の根拠

- **型は導出、人間委譲は証拠つき提案**: 手貼りラベルは腐る（testless gate と同型）。導出で手貼り面を最小化し、導出不能な advisory/detection は
  人間マーカー。委ねる際は `--explain` で「ゼロから導出」を「仮説を証拠と照合」に変える。自動適用は§1の沈黙の腐りに戻るので禁止。
- **measure-\* は advisory（not-a-gate でない）**: フィットネス信号を出し `--strict` で gate 化できる＝価値の問い「信号が消費されるか」が成立。
  collect-gate-history 等の純プラミング（ROI 評価を支える機械それ自体）だけが not-a-gate。
- **メタゲートは untyped のみ叱る**: advisory/not-a-gate は正当な終端。誤分類検出を称すると「存在チェックなのに正しさ保証のフリ」＝沈黙の腐り。
