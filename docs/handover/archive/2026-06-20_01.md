**プローブ責務と型分類の設計判断 decision record（このセッション・コミット予定）**: 「さらに高みを目指すには」の3往復の
議論（A=プローブの correctness 拡張 vs B=ROI 自己収縮）を検証つきで決着させ、`docs/probe-scope-and-gate-classification-decision.md`
（EN単体・160行・decision record 慣習に一致）に正典化。**結論3点**: (1) 生存証明プローブを correctness（正常入力→受理）に
拡張する案は**却下**——correctness は挙動テスト層の責務で `tests/test-check-*.sh` が mktemp+git init で消費者環境も既に再現済み
（`#94` glob 盲点を固定したのがこのテスト群）、かつ誤爆は「沈黙する故障」でなく即顕在化するためプローブ守備範囲外＝重複以前に
「置き場所の誤り」。(2) ROI 剪定に要る予防型/検出型は**手貼りラベルでなく導出**（`REJECT_GATES` 在籍＋clean-accept テスト＝予防型／
`collect-gate-history` が測る＝検出型）。メタゲートは「未分類」可視化のみ担い**意味的誤分類の検出は称さない**（空虚テスト検出と同じ壁・
是正は人間 escalation）。(3) 背景原理「**存在の強制は機械化できるが意味的正しさの強制はできず人間信頼に着地する**」——既存
`escalation-only`（`grep` のみ・意味検証なし）と同じ姿勢。ROADMAP P4「設計上の難所」節からリンク追加。コード変更なし（設計のみ）。

**ゲート型分類の導出 PoC（decision record §3 step1・このセッション・PR 予定）**: §3 の「ROI 自己収縮」第一歩
（型導出）を TDD で実装。問題＝予防型 fires=0(正常) と検出型 fires=0(削除候補) は発火履歴だけでは区別できない
（probe が解いた沈黙の死角の ROI 側再来）。解＝型を手貼りでなく構造導出。`core/scripts/classify-gate-type.sh`（新規・69行）:
`--one <gate>` で reject-type レジストリ在籍⇒prevention／`# gatecrate-type:` マーカー⇒人間上書き／どちらでもなければ untyped。
**在籍が一次でマーカーより優先**（検出型を予防型に偽装しても在籍が無ければ効かない）、逆の誤分類（在籍ゲートに detection
マーカー）は**検出しない**＝意味的正しさは人間 escalation（docs §1 原理の実装）。単一ソース化のため
`probe-gate-liveness.sh` に `--list-reject-gates` 追加（REJECT_GATES 二重定義=drift 防止・性質10 追加で probe テスト36緑）。
`tests/test-classify-gate-type.sh`（5性質）を CI(lint) 配線。**手動欠陥挿入で検出力確認**（変異A=在籍判定常時false→性質1,5落ち／
変異B=untyped→prevention→性質2落ち／復旧6緑）。**kit 自身で実証**: 予防型11／untyped7——untyped7 は全て measure-*/collect-*/
kit-drift/test-compiles/domain-model/gate-tests＝**検出型でなく「測定/advisory 型」**。**発見**: 予防/検出の二分法に第三カテゴリ
（measurement/advisory）が要るかもしれない（これらは reject しないので ROI 剪定の発火判定の対象外＝別扱いが妥当か）。未決定・step2 で判断。

**ゲート型分類 §3.1 精緻化（3カテゴリ+advisory+非ゲート除外・このセッション・PR 予定）**: 「measurement カテゴリ要否」を
ユーザーと議論し決着。**前回の一般化「untyped7 は全て advisory」は誤りと判明し訂正**（実際は test-compiles=検出型・
gate-tests=予防型メタ・残りが advisory/非ゲートの混在）。**核心発見**: prevention/detection/advisory は**スクリプト単体では
導出できない**——measure-* は既定 advisory だが `--strict` で reject、domain-model は反例で exit1 だが required check でない配線で
advisory＝「ブロックするか」はモード(`--strict`)とCI配線(required か)に依存する（§1原理の再来）。**合意した3決定**:
(1)カテゴリは prevention/detection/advisory+untyped、advisory は発火ベース ROI 判定の対象外・終端分類でメタゲートは叱らない、
(2)advisory は step2 では人間マーカー `# gatecrate-type: advisory`（CI配線からの導出は後続）、(3)非ゲート（ハーネス機械/
ユーティリティ）は分類対象外＝`not-a-gate`。実装: `classify-gate-type.sh` に NON_GATE リスト（check-gate-tests のユーティリティ
列挙に整合）と advisory マーカーを追加、判定順 not-a-gate→prevention→マーカー→untyped。テスト9性質（手動欠陥挿入で変異C/D 検出力
確認）。decision record §3.1 に精緻化を正典化。**kit 実証: prevention11／not-a-gate10／untyped6**。**untyped6 の根拠ある型
（step2 でマーカー付与）**: test-compiles=detection／gate-tests=prevention／measure-complexity・measure-coupling・kit-drift・
domain-model=advisory。

**判断材料の提示 `--explain`（§3.2・このセッション・PR 予定）**: ユーザー指摘「意味の正しさを人が判断するのはいいが、判断しやすい
情報を提示してほしい」を受け、§1原理を精緻化。**バレ丸投げ（`untyped` とだけ言う）は当て推量/rubber-stamp を招き沈黙の腐りを人間側に
移すだけ**。正直な設計は「判断を安くする証拠を添えて委ねる」。**境界線**: 自動エンフォース（ラベルを貼って判定まで自動化）は§1が禁じる／
証拠つき提案（派生証拠を全提示+根拠つき仮説・マーカー付与は人間の手作業・**自動適用しない**）は安全——人間の仕事を「ゼロから導出」から
「仮説を証拠と照合」に変える。実装: `classify-gate-type.sh --explain <gate>` が blocks-merge（非0 exit ヒューリスティック）/reject-registry/
strict-mode/self-advisory/behavior-test/in-workflows を出力し、required-check/firing-history は **needs-gh と明示**（憶測禁止）、
suggested type を根拠つきで併記、自動適用しない note 付き。テスト18性質（手動欠陥挿入で変異E/F 検出力確認）。**設計実証**: check-test-compiles の
explain は「blocks-merge: unclear(...verify)」と**誤断定せず正直に保留**し WHY 参照を促した＝ヒューリスティックの限界を honest に扱う設計。
decision record §3.2 に原理を正典化（全ての人間委譲＝removal提案/coverage提案/escalation triage に一般化）。**追加**: suggested type を
**推論のはしご**（observe→select→assume→conclude）で提示し、load-bearing な仮定が needs-gh 依存なら `[UNVERIFIED]`+「check first」で
名指し、飛躍の無い場合（registry 在籍等）ははしごを畳む。テスト25性質（変異G/H で検出力確認）。CURRENT.md は 290行台で archive 検討時期。

## 判断の根拠

- **2層分離（fetch / aggregate）**: 正しさの核（集計）を決定論にしてテスト可能にするため。fetch は gh＋網羅性が
  無いと回らず非決定論なので、ROI 評価の数値正しさを担保する aggregate だけを CI でゲートする。
- **doc churn を collect-gate-history に入れない**: それは CI 履歴でなく git 履歴ソースの axis-2 シグナル。
  SRP（G4）を保つため本スクリプト外とし、評価スキルが git で直接測る設計にした。
- **評価スキルは「薄い実行層」**: 方法論は roi-evaluation.md が正典。スキルで再記述せず手順と罠回避だけ与える。
  剪定の最終判定は persona/人間（exit code に出ない3条件論理積・反事実の罠）。TAKT 化（item相当の P4 三段目）は
  プローブ部分だけが機械判定可で素直に乗る、という ROADMAP の見切りを踏襲（自動ループ化は未着手・任意）。
- **選定ガイドを別資産に**: 「何を作るか（選定）」と「効いているか（剪定）」は別フェーズ。前者は構築時
  （gatecrate-setup の evaluate/profile/consume）、後者は履歴後（gatecrate-evaluate）。両輪として相互リンク。
